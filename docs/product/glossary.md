# Glossary

| Term | Meaning |
|---|---|
| Acceptance criterion | Stable, testable outcome identified as `FNNN-ACNN`. |
| Candidate | Exact source commit and, when built, immutable artifact submitted to QA. |
| Code-switch | A turn containing both Sinhala and English language or script. |
| Feature | Durable user or platform capability identified as `FNNN`. |
| Stage | One production-releasable vertical increment identified by a repository-wide `SNN`. |
| Task | One bounded, assignable unit of stage work, identified as `TNN`. |
| T90 | Mandatory final stage task for independent QA automation and execution. |
| Verbatim transcript | Provider-selected transcript before normalization or LLM repair. |
| Normalized transcript | Separate, versioned representation used for reasoning. |
| UAT | Human client validation of the QA-passed candidate against agreed scenarios. |
| Release authorization | Explicit client production permission plus the release owner's operational go/no-go. |
